# Audit FireWatch CZ – 17. 9. 2026

Výchozí revize: aea734c. Před úpravou: npm test 51/51. Audit zahrnuje všechny zdrojové části repozitáře, routy a databázové operace, workflow i produkční veřejné rozhraní. Produkční přihlašovací údaje a neveřejná data nebyla načítána. Ve veřejné konzoli při základním načtení nebyla zachycena JavaScript chyba. Přístup k produkční SQL databázi / Railway konzoli není k dispozici; rychlost produkčních SQL dotazů nelze vydávat za změřenou.

## Architektura

- Frontend: statický public/index.html, dlouhý klasický public/app.js, styles.css; Leaflet a Chart.js z CDN, mobilní karty a desktop tabulka, přihlašovací/admin dialogy. Dodatečné verze CSS a opakované registrace obsluh způsobují nekonzistenci.
- Server: Node ESM + Express v server.js; JSON limit 2 MB; veřejná data, ingest s X-API-Key, API účtů, OPS/admin oprávnění, geokódování Nominatim, počasí Open-Meteo, CSV a PDFKit exporty.
- PostgreSQL: db.js, parametrizované dotazy přes pg.Pool; events.id je primární klíč, ON CONFLICT aktualizuje. Relace ukládají pouze SHA-256 tokenu, hesla bcrypt. Inicializace přidává chybějící sloupce a tabulky; některé opravné operace mění odhadované délky.
- RSS: rss-worker.js používá fast-xml-parser, Agent/ProxyAgent, oddělené timeouty, maximálně dva pokusy, PostgreSQL advisory lock. scripts/rss-push.js běží na GitHub runneru, přímý feed má RSS2JSON fallback, volitelný gateway klíč požádá až o 100 položek. Bez tohoto klíče má gateway vlastní limit 10.
- GitHub Actions: rss-ingest.yml – ruční spuštění a plán */5, concurrency, npm ci, Node 22, Secrets předávané pouze importnímu kroku.
- Railway: npm start / server.js, databáze přes DATABASE_URL a existující proměnné; nejde o repo obsahující vlastní Railway manifest. Start čeká na DB, pak spouští HTTP, report automatiku, stale closer a RSS worker.
- Souhrny: archived_reports má UNIQUE(period_type,period_key) a bezpečný upsert již nyní. Detail obsahuje JSON snapshot, seznam vybírá jen metadata. Automatika doplňuje poslední den/týden/měsíc; archiv nemá stránkování ani vyhledávání.
- Mapa: Leaflet layerGroup markerů se při refreshi vyčistí, samostatné vrstvy stanic a simulovaných tras. Souřadnice null se chybně převádějí na 0,0; žádná deduplikace vstupních ID, značky nemají rozlišení uzavřených událostí.
- Talk: samostatné public/radio.js + radio.css a radio-server.js, PCM relé /ops-radio, serverová autorita jednoho vysílače v místnosti, heartbeat, dočasné hlasové zprávy/chat v paměti. Reconnect má pevnou prodlevu bez limitu; mikrofon je držen i mimo vysílání.
- Administrace: serverová ochrana requireAdmin/requireOps, cookie HttpOnly/SameSite a DB sessions, ruční změny, ingest diagnostika, audit. Některé volající auditní log předávají nesprávné názvy parametrů.

## Priority a doložené závady

### Kritické

1. Registrace volá createSession se snake_case, přestože DB funkce očekává camelCase; účet může vzniknout a automatické přihlášení selhat.
2. getEventMeta nevrací status_source. Ingest proto nedokáže spolehlivě rozpoznat dříve explicitně otevřenou událost a její uzavírací aktualizaci.
3. Ingest priorita startu umožňuje nové startTimeIso přepsat výpočet délky, zatímco DB zachovává starý začátek; normalizace gateway data zahazuje sekundy. Převod na hranici DST není ověřený.
4. Stale closer popsaný jako ESP-only nerozlišuje RSS/manuální původ a může uzavřít pokračující otevřený zásah bez zprávy zdroje.
5. Generování a automatika souhrnů mají veřejné POST bez autorizace, chybí odmítnutí budoucích období a přísná kalendářní validace.

### Důležité

6. Archiv načte 80 různých typů bez filtru, stránkování a seskupení; datum DATE je ve frontend seznamu technický ISO řetězec. Prázdné snapshoty zastiňují relevantní výsledky. Unikátnost je již zajištěna – migrace na odstranění duplicit není důvodná.
7. V produkční tabulce volba 25 řádků přesto vykreslí všech 31; buildEventsQuery má dvě nastavení limitu, renderTable neaplikuje limit.
8. Souřadnice null/prázdné řetězce jsou považované za 0,0; RSS link je escapovaný, ale není omezen na bezpečné HTTP(S) schéma.
9. Neúspěšný refresh označuje stará data jako OK, přijetí prázdného filtru ponechává předchozí události; datum tabulky závisí na časové zóně zařízení, aktualizační čas se mění i při pouhém překreslení počasí.
10. Duplicitní obsluhy tlačítek fullscreen/mute/TV/audio a tři audio intervaly; opakované obsluhy navigace. Reconnect Talku neomezený, mikrofon se na síťovém pádu a PTT release neuvolňuje, pozdní PTT grant může začít po uvolnění tlačítka.
11. Zápisy auditů používají actor_user_id/detail místo userId/details. Ingest nemá jasný limit počtu položek, počet starších přeskočených událostí a správný RSS source_kind.
12. Veřejné chyby počasí/statistik obsahují text interní výjimky; WebSocket nemá ověřený Origin a běžný výchozí maxPayload je pro PCM zbytečně vysoký. Login limiter bere nedůvěryhodný první X-Forwarded-For a není pravidelně uklízený.
13. Geokódování každého opakovaného ingestu přepisuje souřadnice již známé události, včetně ruční opravy; počasí perioda končí před dneškem.

### Kosmetické a použitelnost

14. Mnoho generací CSS, nepřehledná hustota karet a rozestupy, různé barvy tlačítek/panelů, slabé focus stavy a popisky ikon.
15. Mobilní hlavička a navigace jsou rozměrné, tabulka nemá řazení, archivu chybí přístupné ovládání a srozumitelné prázdné/chybové stavy; modaly potřebují klávesnicové ovládání.

## Výsledná implementace a lokální ověření

- Opraveny relace registrace, názvy auditních polí, admin `is_enabled`, nabídka skutečných rolí a odebrání relací při vypnutí účtu či resetu hesla. Talk pravidelně ověřuje platnost aktivní relace.
- RSS zachovává stabilní ID a původní začátek, prázdný konec neuzavírá zásah, ruční poloha přežije nový import, přes půlnoc zůstávají otevřené události dostupné. Automatické uzavírání je omezeno na ESP. Přímý Agent, ProxyAgent, samostatné timeouty a dva pokusy zůstávají pokryté původními testy.
- Časy používají Europe/Prague, zachovávají sekundy a validují DST i kalendář. Detail uvádí začátek a důvěryhodný konec. Neověřená pozorovaná délka se nevydává za skutečné trvání ani v analytice.
- Archiv používá validované parametry, metadata bez velkého detailu, výchozí stránku 30 a maximum 100, `total`, měsíční skupiny a pokračování přes offset. Čtení neprovádí generování. Zápis vyžaduje příslušné oprávnění. Průměr zahrnuje všechny kalendářní dny.
- Společná komponentová vrstva `public/interface.css` sjednocuje barvy, panely, ovládání, focus, mobilní karty, archiv, dialogy a Talk. Tabulka má funkční řazení a okamžitý limit. Zdroj/obnova má skutečný stav čerstvosti, chyby i prázdný výsledek.
- Mapa odmítá neplatné souřadnice včetně 0,0, deduplikuje události, zeslabuje ukončené markery a dovoluje pouze HTTP(S) odkazy. Stavové počty a návrat na kraj jsou viditelné. Stanice a označené simulace zůstávají zachované.
- Talk otevírá mikrofon až při PTT, bezpečně řeší pozdní grant/permission, uvolňuje mikrofon a omezuje reconnect na šest pokusů. PCM protokol a `/ops-radio` zůstávají zachované. Duplicita audio intervalu a obsluhy audio tlačítka byla odstraněna.
- API má omezené vstupy, bezpečné chyby a ochranu proti cizímu Origin; login/register omezený limiter. Produkční Secrets, prostředí a připojení databáze nebyly změněny. Dev PGlite je izolovaná paměťová databáze, nikoli změna produkčního stacku.
- GitHub RSS výstup uvádí také `skipped` a `skipped_older`; žádné tajné hodnoty neloguje. Railway worker zůstává v projektu.

Ověření před odesláním: čisté `npm ci`, **88/88 testů**, syntax všech **19 JavaScript souborů**, `npm audit --omit=dev` bez známých zranitelností a `git diff --check`. Projekt nemá nakonfigurovaný lint. Integrační testy nepoužívají produkční DATABASE_URL ani produkční klíče. Cílené regresní testy pokrývají účty/relace, skutečné SQL filtry, reporty, chyby API, RSS i reálný WebSocket relay; test klienta vykonává skutečný radio.js s nahrazeným mikrofonem.

První produkční smoke po úspěšném nasazení odhalil také nefunkční CSV export (500): `csvEscape`, `fmtDate` a `fmtDuration` chyběly již ve výchozím server.js. Opravný commit doplňuje bezpečné escapování včetně ochrany před spreadsheet formulí, sdílené časy Europe/Prague a důvěryhodné délky pro CSV/PDF. Oba exporty validují limit. Nový integrační test kontroluje skutečnou odpověď CSV/PDF, filtrování, sekundy, letní čas, neověřené délky i neplatný limit. Po opravě se znovu ověří poslední deployment a produkční exporty.

Pro vizuální kontrolu slouží náhled mimo repozitář se syntetickými 36 událostmi, 110 souhrny a dočasnými testovacími účty. Ověřena šířka 375, 768 a 1440 px, mobilní karty, scroll tabulky pouze uvnitř panelu, detail, archiv, přihlášení, admin a Talk bez aktivace mikrofonu. Produkční výsledky, odkazy na deployment a skutečný RSS workflow budou uvedeny v předaném závěrečném reportu po nasazení.

Migrace: opakovatelně přidány pouze `ingest_log.skipped_count` a `skipped_older_count`, obě int NOT NULL DEFAULT 0. Historie událostí a souhrnů zůstává. Unikátnost `(period_type, period_key)` existovala již před auditem. Návrat znamená nasadit předchozí commit a nové sloupce ponechat. Žádné ruční SQL ani destruktivní testy nejsou potřebné.

Hranice ověření: mikrofon, reálná hlasová kvalita mezi zařízeními, produkční přihlášení bez poskytnutých údajů a výkon při velkém historickém datasetu nelze tímto bezpečným smokem potvrdit. Browser permission a produkční účty se nemění. Stará archivní data jsou snapshoty; pouhé zobrazení je nepřepisuje. Pro více replik je nutný sdílený limiter; prostor pro další práci je profilování velké mapy a postupná konsolidace zbývajícího legacy CSS.
